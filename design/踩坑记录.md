# chatKMS 踩坑记录

> chatKMS 是通用工具，本记录只留**技术教训**，不保留任何具体业务/领域实例。

## 2026-08-10

1. **一次性脚本硬编码业务路径，且创建不幂等**
   曾有初始化脚本把库名/描述/源路径写死在代码里，且 `create_kb` 遇同名目录会**自动加后缀**，重复运行产生多个空壳工作区。
   教训：交互/一次性脚本不得硬编码业务路径（一律从 config.yaml + 已有 .kms 读取）；创建须幂等——同名已存在即报错，绝不静默自增目录名。
   处置：删除该脚本 → 改为通用 `kb_create.py`。

2. **模板文本占位符与 `str.format` 冲突**
   早期把工作区模板文本作为 Python 三引号字符串用 `{name}` `.format()` 注入，占位符风格与 YAML/文本里的花括号易混淆。
   教训：模板改为**文件**（`chatKMS/sample/default`），占位符统一用 `{{name}}` 风格（`{{ }}` 包裹），由 `_substitute()` 做替换，避免与 `.format`/YAML 花括号冲突。

3. **自检脚本的 sys.path 注入曾失效**
   曾把 `Path` 对象直接插入 `sys.path` 导致 `ModuleNotFoundError: backend`（部分 Python 环境对 Path 条目不感冒）。
   教训：统一用 `os.path.dirname` 字符串注入 sys.path。

4. **config.yaml 曾悬空登记不存在的知识库工作区**
   登记了 `workspace: ...\某库` 但磁盘目录不存在 → `get_active_kb` 返回 None（目录检查兜底，没崩，但状态误导）。
   教训：登记与目录创建要保持一致；创建工作区用 `create_kb`（会同时生成目录 + 登记），不要手改 config.yaml 先登记。

5. **模块级变量名被局部变量遮蔽（自检崩溃）**
   `self_check.py` 里用 `wiki = ws / "wiki" / "可信"` 命名局部变量，遮蔽了 `from backend import wiki` 模块引用，调用 `wiki.search()` 抛 `AttributeError`。
   教训：局部变量不要与已导入模块同名；此类问题只有真正跑自检才会暴露——所有代码改动必须跑一遍 `tests/self_check.py`。
