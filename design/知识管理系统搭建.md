# chatKMS — 搭建说明

## 是什么

chatKMS 是一个通用多知识库后端工具：工作区（wiki/RAG/日志）与源文件层分离，源文件只读引用、不拷贝。
AI 终端通过 MCP 接入后，可创建、管理知识库并进行 wiki 优先 + RAG 检索。**纯后端，无界面，唯一接口是 MCP(stdio)。**

## 目录结构

```
chatKMS\
├── readme.md               ← 项目说明（简洁）
├── mcp.json                ← MCP 接入配置
├── kb_create.py            ← 交互式创建知识库
├── config/config.yaml      ← 工作区注册表（只登记 workspace）
├── env/                    ← 环境依赖（requirements*.txt / pyproject.toml）
├── design/                 ← 设计稿 / 搭建 / 评审记录 / 踩坑记录
├── sample/default/         ← 基础工作空间模板（示例，可改）
├── tests/self_check.py     ← 全逻辑自检
└── backend/                ← 后端逻辑（mcp_server / kb_manager / rag / sources / wiki / semantic / nightly_build / config）
```

## 安装

```bash
pip install -r env\requirements.txt
# 可选语义引擎：
pip install -r env\requirements-semantic.txt
```

核心依赖仅 4 个：`pyyaml`、`jieba`、`rank-bm25`、`mcp`。无大模型、无 chromadb，装机即用。

## 接入 MCP

把 `mcp.json` 合并进项目根目录 `.mcp.json`（或 `~/.claude.json` 的 mcpServers 段）；`claude mcp list` 应能看到 `chatkms`。
`CHATKMS_CONFIG` 指向 `config\config.yaml`。命令行验证：`python backend/mcp_server.py`（进入 stdio 等待）。

## 核心概念（AI 终端必读）

| 层 | 位置 | 权限 |
|---|---|---|
| 源文件层 | 工作区**外部**（`.kms` 的 `sources`，可多个） | 只读（source_list / source_find / source_read） |
| wiki 可信 | `wiki/可信/` | 读写 |
| wiki 待确认 | `wiki/待确认/` | 读写（写入后提醒用户确认） |
| 索引 | `.rag/` | 只读（rag_rebuild 生成） |
| 日志 | `log/log_日期.md` | 只追加 |

检索档次：`light`=仅 wiki 快查；`heavy`=wiki+源文件深度；`auto`=wiki 优先补源文件。
RAG 引擎双模式：`bm25`(默认) / `semantic`(装 env/requirements-semantic.txt 后经 MCP 的 rag_engine 切换)。

## 创建知识库

```bash
python kb_create.py
```

输入名称 → 选工作区(默认 workspace_root/名称) → 选/输源路径(可多个，从已有 .kms 快速选或自定义) → 确认。
创建后基于 `sample/default/` 模板生成（复制模板+占位符替换），写入 `.kms` 并登记 config.yaml。

### 自定义基础工作空间
直接改 `sample/default/`（AGENTS.md、结构文件、增删目录）即可，之后创建的所有工作区都会继承；也可在 config.yaml 设 `template_dir` 指向自己的模板目录。

## 自检

```bash
python tests\self_check.py
```

输出 `✅ 全部自检通过` 即核心逻辑正常。**任何代码改动必须能通过自检（见设计稿"设计评审机制"）。**

## 复用

复制 chatKMS 目录 + 改 mcp.json 路径即可在任意机器复用。工具本身不含任何业务/领域术语。
