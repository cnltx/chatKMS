# {{name}} — AI 终端使用指南

本目录是一个 chatKMS 知识库**工作区**，通过 MCP 服务（chatkms）与 AI 终端交互。

## 两个分离的层
- **源文件层**：工作区**外部**的团队原始资料，记录在 `{{name}}.kms` 的 `sources`（可多个）。
  永远只读，不进入工作区。源文件按文件名/相对路径经 MCP 工具（source_list / source_find / source_read）访问。
- **工作区层（本目录）**：chatKMS 生成的全部内容。

## 目录
- `{{name}}.kms` — 自描述文件（只读）：记录本工作区绑定的源路径与作用
- `wiki/` — 生成内容，LLM 可读写，git 管理
  - `可信/` — 有大量佐证、判定可信的知识
  - `待确认/` — 不确定或未经证实，写入后提醒用户确认
  - `结构说明.md` — 目录结构说明，改动 wiki 结构时须同步更新
- `.rag/` — 向量索引（自动生成，勿手动修改）
- `log/` — 操作日志 `log_YYYY-MM-DD.md`（含 git 提交记录与变更设计）
- `AGENTS.md` — 本文件，只读

## 权限
| 目录/层 | 权限 |
|---|---|
| 源文件层（sources） | 只读（source_* 工具） |
| wiki/ | 读写 |
| log/ | 只追加 |
| .rag/ | 只读 |
| AGENTS.md / {{name}}.kms | 只读 |

## 工作规范
1. 新知识入库后**不要全量编译**：先做简单编译保证查询快速且有依据，再在 log/ 记录事件，由子 agent 空闲时补编。
2. wiki 由 LLM 与用户共同维护；用户指出错误时，LLM 先判别再综合写入。
3. 写入 wiki 前辨别是否可考：有大量佐证 → `可信/`；不可信或不确定 → `待确认/` 并提醒用户确认。
4. 每次改动 wiki 后 git 提交，并在 log/ 追加记录。
5. 添加源文件时：只把文件放进源路径（sources 指向的目录），工作区照常引用，无需改动本目录。
6. 若要新增本结构以外的文件或目录，先说明作用，**必须**征得用户同意。
7. 本文件源自 chatKMS 基础工作空间模板（见 chatKMS/sample/default）。如需调整自己的工作区规范，可直接改这份文件。
